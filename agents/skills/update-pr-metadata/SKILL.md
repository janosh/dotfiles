# Update PR Metadata

1. Resolve the current branch's PR once with `gh pr view --json number,url,state,isDraft,title,body,baseRefName,baseRefOid,headRefName,headRefOid,reviewDecision,reviewRequests,latestReviews,mergeable,mergeStateStatus,statusCheckRollup,commits,closingIssuesReferences`. Require `state == "OPEN"`, retain this snapshot, and pass its URL to every later `gh pr` command.
2. Build the projected final scope from `gh pr diff "$pr_url"`, changed files and commits, and local state. Compare `HEAD` with `headRefOid`; inspect `git diff "$headRefOid"` when available, otherwise `git diff HEAD` and identifiable local-only commits; read relevant files from `git ls-files --others --exclude-standard`. The remote diff is authoritative for published code; local commits and working-tree changes signal intended scope. Exclude clearly unrelated work. Never require a clean or aligned checkout, and report behind or diverged state without stopping.
3. Inspect draft/review/merge state, `gh pr checks "$pr_url" --required`, and unresolved `reviewThreads` through paginated `gh api graphql` using the PR URL's host and repository. Report conflicts, requested changes, missing approval, unresolved required conversations, non-passing required checks, and unknown or blocked mergeability as blockers to merging, not to updating metadata. Treat optional check failures as non-blocking unless they expose a real blocker. Separately flag correctness or security risks, missing coverage or docs, artifacts, weak naming, needless complexity, and unDRY code.
4. Inventory each material theme as `<component>: <observable change>`. Use concrete nouns and verbs in a title that covers the major areas, including multi-purpose PRs, and concise component/mechanism/effect body bullets. Include impact, breaking changes, and migration only when relevant. Preserve verified issue-closing references; remove stale claims, boilerplate, commit narration, and `Test plan` or `Verification` sections. Avoid generic wording such as “harden,” “strengthen,” “improve,” “enhance,” “streamline,” “robust,” or “load-bearing,” and do not use Conventional Commit prefixes.
5. Re-read `headRefOid`, `baseRefOid`, title, and body before writing. Recompute scope and metadata if head or base changed; restart if title or body changed. Create a `mktemp` body file with cleanup registered, then run `gh pr edit "$pr_url" --title "$new_title" --body-file "$body_file"`. Re-read and compare title and body exactly; report any failure.
6. Report the PR URL, title change, metadata summary, merge blockers, and polish findings without implying the PR is final.

Only title and body edits are authorized. Keep repository inspection read-only and do not fix code or change labels, reviewers, assignees, milestones, projects, base branch, review state, readiness, comments, commits, or remote refs. A dirty tree, unpushed commits, checkout mismatch, or merge blockers never gate the metadata update.
